# Find Diamonds

A planned free, offline Android ore finder for Minecraft.

## Requirements

- All ore searches run on the Android device. No server, hosted API, account, subscription, advertising SDK, or search limit.
- Enter a world seed, Minecraft edition and generation version, and player coordinates.
- List nearby ore targets with X/Y/Z, distance, and a clear explanation of prediction limitations.
- Save worlds and mark veins as mined locally; keep mined tracking separate for each world, edition, version, and ore type.
- Use an original implementation or appropriately licensed open-source components.

## Current status

Research and requirements only. There is no Android app or working ore engine in this repository yet. Edition and version scope need to be confirmed before implementing generation logic.

## How this kind of finder works

Minecraft world generation is deterministic for a given seed and generation configuration. A seed-based finder reproduces the relevant random number generators and feature placement rules near the requested coordinates. Calculations can run locally; a paid backend is not intrinsically required.

Candidate ore placement alone does not reproduce terrain replacement, caves, air exposure, biome checks, previous mining, or all generation interactions. A seed-only implementation must describe candidates honestly and be tested against real game-generated worlds before advertising accuracy.

Java and Bedrock require separate implementations. Java results must never be relabelled as Bedrock results. Chunks first generated in an older game version keep their existing blocks after an upgrade.

## Research sources

- [Find Diamonds: Ore Finder — Android listing](https://play.google.com/store/apps/details?id=com.rushedbytes.diamondsfinder): describes seed and coordinate input and ore results. This listing does not establish its internal algorithm or whether its calculations run remotely.
- [Meteor Rejects OreSim](https://github.com/AntiCope/meteor-rejects/blob/master/src/main/java/anticope/rejects/modules/OreSim.java): a public Java implementation illustrating decoration seeding, per-feature random streams, and vein generation. Its code relies on Minecraft runtime classes and world data, so it is not a drop-in Android engine.
- [Meteor Rejects ore configuration](https://github.com/AntiCope/meteor-rejects/blob/master/src/main/java/anticope/rejects/utils/Ore.java): obtains generation parameters and feature indices from the game's registries. Those parameters must be pinned to the supported game version in a standalone app.

## Planned implementation

1. Confirm target edition(s) and generation version(s).
2. Create a native Android project with a separate pure calculation module.
3. Implement and independently verify the version-specific RNG and feature configuration.
4. Compare predicted locations against fixtures generated by the matching game version, including negative coordinates and chunk boundaries.
5. Add the search interface, local saved worlds, mined tracking, and cancellation of background searches.
6. Build an installable APK and test offline operation on Android.
